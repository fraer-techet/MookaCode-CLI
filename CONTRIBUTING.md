# Contributing to MookaCode

Спасибо, что хотите помочь. Проект маленький, поэтому процесс простой.

## Требования

- Node.js **20.11+**
- pnpm **11+** (`corepack enable` подхватит версию из `package.json`)

## Настройка

```bash
git clone https://github.com/fraer-techet/mookacode.git
cd mookacode
pnpm install
pnpm verify
```

`pnpm verify` — это `typecheck` + `lint` + `test` + `build` + `smoke`. Именно это гоняет CI, и именно это нужно получить зелёным перед PR.

Запуск CLI из исходников без сборки:

```bash
pnpm dev "объясни, что делает packages/core/src/agent/engine.ts"
```

## Структура

| Путь                | Что там                                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `packages/cli`      | TUI, readline, подтверждения, команды, ANSI-рендерер                                                                            |
| `packages/core`     | конфигурация и ключи, провайдеры, агентский цикл, инструменты, permissions, сессии, контекст и память, Git, LSP, MCP, субагенты |
| `packages/protocol` | общие типы и события                                                                                                            |
| `docs`              | архитектура, конфигурация, безопасность, тесты, troubleshooting                                                                 |
| `scripts`           | сборка, smoke, установка                                                                                                        |

Правило: Core не знает про CLI. Всё, что нужно интерфейсу, идёт через `MookaCore` и типы из `@mookacode/protocol`.

## Стиль кода

- TypeScript, строгий режим, ESM, `verbatimModuleSyntax`.
- Форматирование — Prettier: `pnpm format`. Проверка — `pnpm format:check`.
- Линт — ESLint: `pnpm lint`. Предупреждения не ломают CI, ошибки ломают.
- Комментарии и идентификаторы — по-английски, пользовательские строки CLI — по-английски, документация — как в соседних файлах.
- Новые зависимости обсуждайте в issue: проект сознательно держит дерево зависимостей маленьким.

## Тесты

- Юнит- и интеграционные тесты — Vitest, лежат рядом с пакетами в `packages/*/test`.
- Для агентских сценариев используйте fake OpenAI-compatible SSE-сервер (`packages/core/test/helpers/fake-openai.ts`), а не реальный API.
- Тесты не должны ходить в сеть, требовать ключей или писать в `~/.mookacode`.

```bash
pnpm test
pnpm test -- packages/core/test/agent-loop.test.ts
```

## Коммиты и PR

- Один PR — одна тема. Рефакторинг и поведение не смешивайте.
- Сообщение коммита: короткая строка в императиве (`fix: keep session resumable after 401`), тело — по желанию.
- В описании PR укажите: что изменилось, зачем, как проверяли (`pnpm verify` + ручной сценарий).
- Ломающие изменения и изменения формата конфигурации/сессий — отдельно и с миграцией.

## Безопасность

Не открывайте публичный issue на уязвимость. Порядок описан в [.github/SECURITY.md](.github/SECURITY.md).

Отдельно: MookaCode **не** является песочницей. Любой код, который исполняет команды, должен уважать workspace-guard и permission-политику. PR, ослабляющие эти проверки, не принимаются без очень весомой причины.
